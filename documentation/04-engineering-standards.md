# 工程标准

## 1. 文档

1. 每个 crate 根启用 `#![deny(missing_docs)]`。公开项必须有文档，不接受用 `allow` 绕过。
2. 模块级文档说明职责与边界，不只是复述函数名。
3. 注释解释“为什么”，不复述代码“做了什么”。
4. 公开文档只描述产品语义与可观察行为。内部实现细节、私有路径与未发布计划不进入公开文档。

## 2. 测试

1. 测试放在 crate 的 `tests/` 目录，不写回 `src/` 内的 `#[cfg(test)]` 模块。
2. 测试按用途分层：acceptance（行为合同）、integration（跨模块主链）、fixtures（共享构造）。
3. 崩溃与恢复类测试必须真的模拟中断：截断文件、删除 companion、在提交中间停止，而不是断言时间或睡眠。
4. 存储与协议测试必须有字节级 golden。golden 变更即格式变更，需要按兼容规则判定。
5. 回归测试固定缺陷的 **可观察行为**，不为内部实现细节写断言。
6. 一个缺陷的修复与其回归测试属于同一个变更。

## 3. 格式与静态检查

| 范围              | 工具                                                             | 门槛                             |
|-------------------|------------------------------------------------------------------|----------------------------------|
| Rust              | `rustfmt`，工具链 pin 在 `rust-toolchain.toml`                   | `cargo fmt --all --check`        |
| TypeScript / 配置 | Nifty preset                                                     | `pnpm exec nifty format --check` |
| 编译              | `cargo test --workspace` 与 `cargo build -p yydb-napi --release` | 必须通过                         |

规则：

1. 不为通过检查而放宽 lint 或删除文档检查。
2. 格式化只改变排版，不得改变 token 语义。出现语义变化视为缺陷。
3. `Cargo.lock` 与 `pnpm-lock.yaml` 不纳入版本控制。CI 使用无 frozen 安装。
4. `.cargo/config.toml` 是本机 path patch 与 registry override，被忽略，且不得提交。

## 4. CI

1. Rust 检查在三平台（Linux / macOS / Windows）运行，任一失败即不可合并。
2. TypeScript 检查负责 wasm 构建、Nifty 格式、各前端构建与测试。
3. 发布工作流与 CI 独立：发布不等待 CI，CI 通过也不代表已发布。
4. 新增检查必须能本地复现；不能本地复现的门禁不接受。

## 5. 依赖

1. VOS 的语法与语义由上游拥有。YYDB 不复制 parser、不 vendor 上游源码、不维护平行语法模型。
2. 上游行为不满足需求时，先在上游修，再升级依赖；不在本仓打补丁绕过。
3. 依赖升级后必须重新跑存储与协议 golden，避免编码在依赖变化中漂移。
4. 绑定依赖（N-API、PyO3、wasm-bindgen）只出现在绑定 crate。

## 6. 变更卫生

1. 一个可独立说明、独立验证、独立回滚的逻辑块对应一个提交。无关修改不得混入。
2. 提交前检查工作树差异与相关测试；只暂存本逻辑块涉及的文件。
3. 破坏性重构与行为变更分开提交。
4. 删除能力时同时删除其公开入口、测试与文档，不留“暂时保留”的兼容壳。

## 7. 发布

1. npm 真实版本只经 tag `vX.Y.Z` 触发 OIDC 发布，禁止本地 `npm publish`、token 或 OTP 旁路。
2. 发布版本来自 tag，不来自 `package.json`。包内版本字段是基线，不是发布声明。
3. 已发布版本不会被重写。重试是幂等的：已存在版本跳过。
4. `0.0.0` 只用于占位 stub 与 Trusted Publisher 配置，不是发布版本。
5. Rust crate 发布与 npm 发布是两条独立链路，不能用其中一条的通过证明另一条已完成。
