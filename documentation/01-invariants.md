# 不可破坏的不变量

这些规则描述 YYDB 是什么。任何实现改动都不能在未修改本文件的前提下破坏它们。

## 1. 语言与 schema

1. **VOS 是唯一的 DDL 与查询语言。** YYDB 不自造私有 schema 方言，也不在大版本内切换语言。
2. schema 文档是数据库真相的一部分：它随主文件或同一个 WAL 快照发布，不能与记录状态分裂成两次提交。
3. 语义检查由 VOS 合同拥有。YYDB 消费检查结果，不在本地复制 parser 或平行类型系统。
4. schema 变更走显式入口。读路径不得隐式改写数据库 schema。

## 2. 持久化布局

1. **`.yydb` 只有一个持久数据文件**：主文件。`-wal` 与 `-shm` 是可删除的 companion，不是数据库数据。
2. companion 的“可删除”有前提：已提交内容必须已经 checkpoint 到主文件，且没有活跃读写者依赖它。禁止在未 checkpoint 时丢弃已提交
   WAL。
3. **`.yydx` 才允许同级对象目录**：`<app-name>-objects/` 下的 `.blob` 段属于持久数据，不能当 companion 删除。
4. 禁止创建或恢复 `<app>.yydb.objects/` 这类旧式 sidecar。单文件模式不得依赖持久 sidecar 才能读回数据。
5. 行内字节能存小值，`INLINE_BYTES_MAX`（4 KiB）是 **软建议阈值**，不是硬校验。超过阈值的载荷应进入 CAS。
6. 大文件是分块 manifest，不是把整文件塞进一条记录。向量与 ANN 段与普通对象共用同一 CAS。

## 3. 身份稳定性

1. 类型与字段的 durable identity 不来自源码顺序、文档顺序或遍历顺序。
2. `virtual_field_index: Option<u32>`：`Some` 表示该字段确有持久存储槽，`None` 表示 durable 存储不覆盖它。槽位获得与丧失是显式变更。
3. 槽位永不复用：字段退休后其槽位不能分配给新字段。
4. rename 与 reorder 不改变 identity。只有显式删除或新增才改变集合。
5. 没有持久 identity 来源时，不得用“当前顺序”伪造稳定性来生成协议或文件。

## 4. 对象与引用

1. CAS 按内容哈希寻址，同一内容只存一份。
2. 删除或回收对象前必须先核对引用。孤儿判定只能来自对已提交记录与 manifest 的扫描，不能靠时间或文件年龄猜测。
3. 被 pin 的对象不参与回收。
4. 对象缺失、哈希不匹配、段损坏都是结构化错误，不得返回空值或部分内容。

## 5. 并发与事务

1. 单写者：文件库由操作系统独占锁保护，多进程同时写不被允许。
2. 读操作不得看到未提交的中间状态。
3. KV 事务是连接内的快照；schema / DDL 调用不进入 KV 事务边界。
4. 事务回滚必须同时丢弃记录与元数据变更，不能只回滚其中一半。
5. 崩溃恢复只重放完整事务。尾部不完整事务被丢弃，已提交事务不得被重写或跳过。

## 6. UDF

1. UDF 是 **进程本地**能力，不写入 `.yydb` 文件。重新打开数据库后需要重新注册。
2. UDF 的 effect 与 placement 是合同的一部分，参与注册验证；不符合本地只读条件的实现必须被拒绝。
3. host micro 由宿主进程注册并通过回调执行，不属于数据库持久状态。
4. UDF 版本与签名不匹配时返回结构化错误，不允许静默降级到同名旧实现。

## 7. lease 与配额

1. lease 与 fencing token 存放在保留键空间中，不污染用户命名空间。
2. fencing token 单调递增；过期 lease 的写入必须被拒绝，不能被“最后一次写入获胜”覆盖。
3. lease 回收是显式动作，不依赖后台线程的隐式清理。
4. 配额与淘汰必须返回可观察的报告。禁止在用户不知情的情况下静默丢弃已提交数据。

## 8. 健康检查

1. `doctor` 是只读诊断，不得修改文件、修复数据或触发 checkpoint。
2. 诊断结果分级（severity），并提供机器可读字段；人类可读文本只是展示层。

## 9. 服务与安全

1. 参考 `yydb serve` **没有 ACL**：能连接 socket 的人就能读写数据库。
2. 默认只绑定 loopback。非 loopback 必须显式开启并给出警告。
3. 信任边界是进程部署位置与 `.yydb` 的文件系统权限，不是协议内的认证。
4. YYDB 不内置遥测、审计与上报。需要这些能力的产品应在自己的层实现，不得偷偷塞进参考实现。

## 10. 错误与兼容

1. 错误是对外合同：`code` 稳定，`message` 只是展示文本，可以随版本变化。
2. 调用方只能根据 `code` 与结构化字段分支，不能解析 `message`。
3. 未知格式版本、未知消息类型、未知枚举值一律拒绝，不猜测、不降级、不部分应用。
