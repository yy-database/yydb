# UX / DX 准则

本文件约束“别人怎么用 YYDB 的代码”，不是终端用户教程。这里只记录作者面、错误面与绑定层的设计准则；具体 API 用法见各 crate 的
`readme.md` 与 docs.rs。

## 1. 错误模型

1. 错误必须可分支：稳定标识是 `yydb::Error::code()` 返回的字符串，完整清单见 [
   `03-encoding-and-compatibility.md`](./03-encoding-and-compatibility.md) §2。客户端只能对 `code` 分支。
2. `message` 是显示文本，可读、可翻译、可随版本变化。任何代码不得解析 `message` 做判断。
3. 新增失败路径必须落到已有 `code` 或新增 `code`。用 `yydb.io` / `yydb.unsupported` 兜底而不加语义，视为错误分类缺失。
4. 错误必须携带上下文：至少能说明失败的操作（读、写、schema、UDF、协议、lease）与对象。上下文放结构化字段，不靠拼字符串。
5. 跨 FFI / 跨进程边界不得 panic。绑定层必须把 panic 转成错误值；`unwrap` / `expect` / `panic!` 只允许出现在测试与不可能分支，并附理由。
6. 可以重试的失败必须显式标注（`retryable`），与不可重试的失败区分。调用方不应靠猜 `code` 名字判断重试。
7. 错误类型不得泄漏内部实现：不暴露 pager、帧缓冲区、锁内部状态等类型给宿主。

## 2. 诊断

1. `doctor` 一类的诊断入口只读：不修复、不迁移、不写文件、不获取写锁。
2. 诊断输出必须同时有机器可读结构与人类可读摘要；结构字段稳定，摘要措辞可变。
3. 每条诊断带严重级别（如 info / warning / error）与稳定标识，不使用自由文本作为唯一标识。
4. 诊断不得静默吞掉问题。发现问题就必须报告，即使当前不影响打开。
5. 诊断不承担遥测职责：不上报、不联网、不落匿名统计。

## 3. 作者面

1. 一个能力只有一个公开入口。同一操作不同时提供同步与异步、高低层两套平行 API。
2. `Connection` 是嵌入宿主唯一句柄。打开、schema、读写、对象、lease 都从它出发，不为子能力再发句柄。
3. 门面只重导出与组装，不发明新语义（见 [`02-architecture.md`](./02-architecture.md) §3）。
4. 默认路径必须安全且够用：`Connection::open` 直接可用，危险能力（非 loopback 绑定、覆盖写、强制回收）需要显式选择。
5. 命名表达产品语义，不表达内部结构。不出现以 crate 名、缓冲区名、页名命名的方法。
6. 不为“以后可能需要”预留参数、泛型或 trait。新增扩展点必须有当前调用方。
7. 破坏性变更直接改签名并同步所有调用方，不留 deprecated 兼容壳（见 [
   `04-engineering-standards.md`](./04-engineering-standards.md) §6）。

## 4. 绑定层（N-API / PyO3 / wasm）

1. 绑定层只做类型与生命周期映射：语言类型 ↔ Rust 类型、句柄生命周期、回调注册。不重写存储、不重写协议、不重写 schema 校验。
2. 绑定层必须原样保留 `code`，并可附带 `operation` 与 `retryable`。不得把多个 `code` 合并成一个通用“数据库错误”。
3. 绑定层不得改变默认行为：默认绑定地址、默认配额、默认事务边界与 Rust 面一致。
4. 绑定层不得增加隐藏重试、隐藏重连、隐藏 flush。需要这些策略时由调用方显式选择。
5. 异步边界必须明确：哪些调用阻塞、哪些返回 Promise/Future、取消语义如何。不允许同一方法在不同绑定里语义不同。
6. wasm 绑定不得假装拥有文件系统能力。能力缺失必须返回 `yydb.unsupported`，不得回落到静默内存模式。

## 5. 线协议客户端

1. 客户端只对 `code` 分支，不解析 `message`。
2. 重试依据结构化字段（`code` + `retryable`），不依据字符串匹配或固定次数盲重试。
3. 客户端必须处理服务端主动推送（`MicroHostInvoke`）与请求响应的交错，不能假设一问一答严格串行。
4. 未知 `msg_type`、未知版本、未知 magic 一律拒绝并报 `yydb.protocol`，不得猜测降级。
5. 客户端不得自行放宽帧上限、body 上限或长度字段校验。
6. `@yydb/yydb-client` 与 Rust `yydb-client` 对同一帧必须产生等价的错误分类。

## 6. 安全默认

1. 无隐式网络：嵌入模式不监听端口，不发起连接。
2. `serve` 默认只绑 loopback；非 loopback 需要显式开关并打印警告（见 [`01-invariants.md`](./01-invariants.md) §9）。
3. 无遥测、无后台上报、无自动更新检查。
4. 日志默认不记录数据内容与密钥；需要排查时由调用方显式提升级别。
5. 参考实现不含认证与授权。不得把“没有 ACL”包装成安全默认，也不得在参考实现里静默加入半成品权限层。

## 7. 判定表

| 变更           | 接受                   | 拒绝                          |
|----------------|------------------------|-------------------------------|
| 新增错误码     | 有稳定语义与触发条件   | 用 `yydb.io` 兜底表达业务失败 |
| 错误信息改写   | 只改 `message`         | 改 `code` 或让调用方依赖文本  |
| 新增公开方法   | 同一入口的明确能力     | 为同一操作加平行同步/异步 API |
| 绑定层新增逻辑 | 类型与生命周期映射     | 重写存储、协议、校验或加重试  |
| 诊断扩展       | 只读、结构化、稳定标识 | 顺带修复文件或联网上报        |
| 安全相关默认值 | 更安全且可显式放开     | 为方便默认放开网络或权限      |
