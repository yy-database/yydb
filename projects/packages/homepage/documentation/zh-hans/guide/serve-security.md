# Serve 安全模型

<div class="warn">

参考实现 **`yydb serve` 没有权限管理系统**（无 login / 用户 / 角色 / ACL）。 连上 socket 的客户端可以读写已打开的数据库。前端协议客户端同样不承担鉴权。

</div>

因此 **YYDB** 的产品设计是：

1. **默认只绑 loopback**（`127.0.0.1` / `::1`）。
2. 非 loopback 必须显式 `--insecure-bind`，启动时会打印强警告。
3. **不要把 `yydb serve` 暴露在公网上。**
4. 本机文件权限（谁能读 `.yydb`、谁能起进程）仍是信任边界的一部分。

需要 **内置权限、自动审计、调优上报** 等默认就很重的控制面时，应使用 **YYDS**
（面向分布式大客户），而不是把 YYDB 长成迷你 YYDS。线协议上 `YYDB`/`YYDS`
魔数只是后端自称、效果相同；前端不强求一致，但产品能力完全不同。
